# App 通用设置：多语言与主题

状态：产品要求；整个 App 适用，已授权纳入第一版实现。本文定义行为，实际完成和验证状态见 [MVP 执行记录](MVP-EXECUTION.md)。

## 1. 多语言

- 全部应用页面、菜单、弹窗、提示、错误、播放器自定义控件和可访问标签支持本地化，集中管理文案。
- 支持跟随系统与手动选择语言，默认跟随系统；手动选择后系统语言变化不覆盖用户选择。
- 切换即时生效，无需重启，不丢失表单输入、不重建房间或播放会话。
- 日期、数字、单位、复数及参数化提示按语言处理，不拼接完整句子。
- 昵称、文件名、媒体标题和 URL 保持原文；底层错误映射为可翻译的提示，技术诊断可保留原文。
- 首版建议简体中文、英语，具体语言清单及默认回退语言在实现前确认；缺失翻译有回退，不显示资源键或空白。

## 2. 主题切换

支持浅色、深色、跟随系统，默认跟随系统。系统主题变化仅影响跟随系统模式，不覆盖手动模式。

覆盖页面、侧栏、弹窗、菜单、表单、提示、加载/空状态和播放器自定义控件。视频内容本身不着色；原生文件选择器等系统界面按平台能力适配。

## 3. 主题色按主题独立配置

| 配置 | 含义 |
|---|---|
| themeMode | 浅色 / 深色 / 跟随系统 |
| lightThemeColor | 浅色主题色，独立保存及恢复默认 |
| darkThemeColor | 深色主题色，独立保存及恢复默认 |

禁止以一个可变颜色值同时覆盖明暗配置。设置页分别提供“浅色主题色”和“深色主题色”入口和预览；编辑非当前主题的颜色只更新对应配置，不强制切换主题模式。

示例：浅色设蓝、深色设紫。切到浅色用蓝，切到深色用紫；浅色改绿后深色仍为紫。跟随系统时按实际生效的明暗主题读取各自颜色。

两套主题有各自默认值，重置浅色不影响深色和主题模式，反之亦然。主按钮、选中态和强调元素使用主题色；背景、表面、文字、边框、禁用和交互态按明暗分别构建语义配色，不能直接共用同一套颜色。错误、警告、成功保留语义，状态不能只靠颜色传达。

预设色或任意选色在视觉设计时确定；均需满足文字和交互对比度要求。

## 4. 保存和生效范围

语言模式/手动语言、主题模式、浅色主题色、深色主题色保存在本设备，重启恢复。损坏或不支持的字段单独回退默认，不清空其他有效配置。

任意房间角色可修改自己的设置；不广播到房间，不影响其他成员，不触发重新连接、缓冲或共享播放控制。不涉及账号与云同步。

## 5. Flutter 约束

使用集中本地化资源和统一主题入口。应用根节点选择对应主题，业务组件消费语义颜色，不各自维护主题色状态。偏好采用工程已有或适用的本地存储；当前不引入实现或额外框架。

## 6. 验收

1. 切换语言后所有应用文案和可访问标签更新，长文本不溢出，缺失项有回退，用户内容保持原文。
2. 手动/系统语言行为正确，重启保持选择。
3. 明暗及跟随系统模式正确，手动模式不被系统覆盖。
4. 明暗主题色独立修改、重置、预览与持久化，反复切换不串色。
5. 编辑非当前主题颜色不强制更改主题模式。
6. 全局组件配色一致，对比度、焦点、禁用和错误状态清晰。
7. 切换语言/主题不丢失输入，不影响播放、缓冲、连接、进度及权限，不向他人广播外观设置。
8. 损坏字段独立回退，其他设置保留。

## 7. 后续自定义外观开发与切换

整个 App 的外观应允许开发者后续扩展并切换，不局限于主题色：包括配色、字体、圆角、间距、图标/素材、组件样式和必要的页面呈现变体。这里只约定可扩展方向，不要求第一版交付多个外观或任意布局编辑器。

外观方案与明暗模式分开：用户选定外观方案后，仍可选择浅色、深色或跟随系统。每个外观方案的明暗配色分别定义；原有主题色设置按“外观方案 × 浅色/深色”隔离保存，切换方案不覆盖其他方案的配置。

后续新增方案通过正常开发、审核和构建交付，再由设置入口切换；不要求运行时下载执行代码。外观配置不承载播放、网络、权限等业务逻辑；现有页面优先通过主题、共享组件及布局组合扩展，避免为每套外观复制页面与业务。

外观切换保持当前页面、表单、播放和连接状态，已选方案本机持久保存；方案移除或不可用时回退内置默认外观，其他有效偏好保留。所有方案均需覆盖已支持页面、语言与明暗模式，满足可访问性。

优先复用 Flutter 原生主题、组件样式及适合的成熟库，只在框架无法表达的真实需求上增加少量扩展。第一版只建立一致的外观入口，不提前开发皮肤框架。

后续交付验收：开发一个附加外观不改动同步/权限业务；可反复切换并重启恢复；不同外观的明暗主题色互不覆盖；切换不影响观影，缺失方案能安全回退。
