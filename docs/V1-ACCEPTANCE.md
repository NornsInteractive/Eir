# 第一版验收与实施计划

> 实施范围更新：用户已授权开始实现，首版覆盖 Windows/macOS/Linux/Android/iOS/Web。本文早期“仅设计”“桌面先行”“移动/Web 后续”及桌面停止条件由六端范围替代；平台专属媒体实现仍需逐端验证。执行约束与进度以 [IMPLEMENTATION.md](IMPLEMENTATION.md) 为准。

状态：待执行；本文列出未来检查，不代表已有代码、测试或性能结果。

## 1. 开发前验证门槛

| 编号 | 验证 | 通过证据 |
|---|---|---|
| G1 | 三桌面 WebRTC 互通、指纹绑定、背压、ICE 重启 | 跨系统连接记录、篡改握手拒绝、队列有界 |
| G2 | 文件 remux → P2P → 缓存 → loopback HLS → 播放器 | 两台真机边收边播、未完整下载即可播放、随机 seek |
| G3 | 同步精度与播放器控制 | 实测位置/画面偏差、速率修正、暂停与恢复数据 |
| G4 | URL 点播和文件格式边界 | MP4/HLS、无音轨、长 GOP、不兼容和损坏样本结果 |
| G5 | 打包与依赖 | Win/macOS/Linux 可安装运行，媒体工具和依赖许可记录 |

任一关键能力失败先修订设计，不先展开完整 UI。候选依赖锁定版本、缓存默认容量、磁盘最低空间、线格式字节布局及限流数值必须在协议冻结清单中补齐；这些是进入实现前的明确待决项。

## 2. 实施顺序

1. 冻结第一版范围、身份/邀请规则、协议测试向量和错误码表。
2. 完成 G1/G2/G3 关键链路验证，记录平台能力及限制。
3. 实现创建/加入、角色签名、快照与有序提交。
4. 实现 URL、本地媒体、列表、同步与状态呈现。
5. 实现重连、空间不足和生命周期恢复，完成跨系统验收。

当前修复停止条件：Web 双独立身份及 Android App＋Web 的本地/URL 同步观影、权限与恢复流程有实际播放证据，设置空白和本轮列出的核心缺陷关闭。其他平台目标保留，未提供运行环境的验证缺口必须单列；不能把当前两端通过写作六端通过。本次不追加多人、自动转码或 TURN 接入。

## 3. 功能验收矩阵

| 编号 | 场景 | 预期 |
|---|---|---|
| A01 | 创建、邀请、加入 | 身份绑定正确，第三个身份因两人上限被拒绝 |
| A02 | 邀请重试/重放 | 原身份重试幂等，其他身份不能复用已消费邀请 |
| A03 | 管理员增撤 | 授权后可控，撤销提交后新控制请求被拒绝 |
| A04 | 成员改客户端发控制 | 接收端验权拒绝，房间状态不变 |
| A05 | 添加 HTTPS MP4/HLS 点播 | 两端各自访问，时长与播放可用；单端失败独立提示 |
| A06 | 过期/网页/直播/DRM URL | 拒绝或明确报告不支持，不由信令代抓 |
| A07 | 本地兼容文件 | 原文件不改动，切片校验，观众未收完整视频即可播 |
| A08 | 不兼容/损坏/长 GOP | 不隐式转码；报错或展示已知准备/seek 成本 |
| A09 | 播放、暂停、seek、倍速 | 按同一序列生效，重复请求不重复执行 |
| A10 | 列表并发、删除和替换当前项 | 行为符合 V1-PRD，旧下载不污染新媒体 |
| A11 | 自然结束/列表末尾 | 房主唯一提交下一条；末尾停播，不重复跳转 |
| A12 | 晚加入和个人缓冲 | 其他人继续，加入者缓冲后追赶 |
| A13 | 原源退出 | 缓存可播，缺片等待，无不存在的接力承诺 |
| A14 | 房主离线/恢复 | 当前项继续，禁止新控制与自动下一条，恢复重新对齐 |
| A15 | 信令断开/重启 | 原连接继续；房主重建登记，旧邀请代次失效 |
| A16 | P2P 故障、休眠、网络切换 | 有界重试，失败可见且可手动重试 |
| A17 | 空间不足/中断准备/清理缓存 | 不破坏原文件，不删在用缓存，临时文件可清理 |
| A18 | 可访问性 | 键盘可操作、焦点明确、只读与本地控制正确区分 |

## 4. 安全与协议检查

必须覆盖伪造签名、替换房主公钥、伪造成员接纳、重用随机挑战、DTLS 指纹不匹配、跨房/跨会话重放、撤销权限、重复提交、乱序缺号、快照倒退、同序号冲突、清单替换、坏片、越界块、重叠冲突、超大消息和请求洪泛。

检查 loopback 服务无法从外网访问、不接受目录遍历、无令牌无法读取；检查 URL 与文件名无法注入外部命令；检查日志不含秘密和完整媒体令牌。

## 5. 性能口径

| 指标 | 验收口径 |
|---|---|
| 状态可见 ≤3 秒 | 支持网络、双方应用运行、凭证有效，从点击加入到验证快照显示；不含媒体准备 |
| 连接 ≤5 秒 | 同条件下，从点击加入到 P2P 身份握手完成 |
| 操作响应 ≤1 秒 | 已缓冲，两端前台，从管理员发出到最慢端实际生效 |
| 稳态偏差 P95 ≤150 ms | 已缓冲前台双端，同一时刻两端媒体位置差；另报告画面测量与方法 |
| 缓冲/故障 | 单独报告时长、次数及恢复时间，不混入或隐去稳态样本 |
| CPU/内存 | 原 PRD 的单核 15% 与核心内存 300 MB 是目标，需标明硬件、是否含 Flutter/解码/切片进程及测量方式 |

固定记录操作系统、硬件、视频编码/码率/GOP、网络 RTT/丢包、样本数。覆盖同局域网、不同家宽、移动热点及受限网络；无 TURN 时记录连接失败，不按原愿景的 98% 兜底成功率验收。

使用高码率样本测供片带宽，30 秒缓存需求约为码率 × 30 / 8；例如 8 Mbps 约 30 MB，另计播放器缓冲。文件完整准备时间与体积单独报告，不能计成纯网络开播耗时。

## 6. 测试与发布产物

纯逻辑测试：可注入单调时钟、offset/漂移、排序与去重、权限链、清单哈希和请求取消。集成测试：双客户端、信令、媒体缓存及故障注入。真机测试：解码、画面精度、休眠和跨网络。

交付时至少提供：可安装桌面包、运行与部署说明、锁定依赖/许可证、协议测试向量、跨平台矩阵、已知限制、自动化测试结果、性能与失败样本。服务只需 WSS 与 STUN；不声明未经压测的 2000 房间容量。

## 7. 开发方式与外观扩展检查

遵循 [项目开发原则](DEVELOPMENT-PRINCIPLES.md)，检查新增功能是否先评估复用与成熟库、选型依据是否充分、是否存在重复逻辑或仅转发的封装。第一版检查外观统一入口、业务分离及明暗配置隔离；附加外观的开发/切换/恢复验收在实际交付该能力时执行，不将多个外观或皮肤框架加入第一版范围。
