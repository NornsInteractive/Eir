# 第一版需求与业务规则

> 实施范围更新：用户已授权开始实现，首版覆盖 Windows/macOS/Linux/Android/iOS/Web。本文早期“仅设计”“桌面先行”“移动/Web 后续”及桌面停止条件由六端范围替代；平台专属媒体实现仍需逐端验证。执行约束与进度以 [IMPLEMENTATION.md](IMPLEMENTATION.md) 为准。

版本：v0.1；状态：待评审；技术约束：Flutter；不含实现代码。

## 1. 目标与范围

让两台设备进入同一房间，同步观看本地视频或 URL 点播视频。平台目标为 Windows、macOS、Linux、Android、iOS、Web；当前修复与逐项验收顺序见 CURRENT-REPAIR-PLAN.md。添加本地文件不需要上传到服务器，另一设备无需提前持有文件或完整下载。

| 纳入第一版 | 暂缓 |
|---|---|
| 多语言、主题切换、明暗主题独立主题色 | 云端偏好同步 |
| Windows、macOS、Linux、Android、iOS、Web；最多两台设备 | 多人房间 |
| 创建、邀请、加入、离开、解散 | 账号、社交、聊天、审批、投票 |
| 房主、管理员、成员；房主固定 Leader | 自动选主、自走续播、房主转让 |
| 成熟播放器及目标平台能解码的本地视频，可无音轨；不可按两个扩展名白名单限制 | 自动转码、平台嵌入、直播、DRM |
| HTTPS MP4/HLS 点播直链 | URL 代取、自定义 Cookie/请求头、视频托管 |
| 播放、暂停、seek、倍速、列表与自动下一条 | 多人 Swarm、下一条媒体预取、等待所有人 |
| 当前视频缓冲、漂移纠正、签名验证、重连 | TURN 产品兜底、UPnP、后台持续供片保证 |

本版仅支持可建立 WebRTC 直连的网络。失败要明确告知，不能承诺任意两地可连。HTTPS 是远端 URL 默认入口，设备内 loopback 媒体地址不受此用户输入规则影响。

## 2. 角色与权限

| 操作 | 房主 | 管理员 | 成员 |
|---|---|---|---|
| 观看、查看成员位置/缓冲 | 是 | 是 | 是 |
| 本机音量、全屏等本地操作 | 是 | 是 | 是 |
| 播放、暂停、seek、倍速、切换 | 是 | 是 | 否 |
| 添加、删除、排序、替换列表项 | 是 | 是 | 否 |
| 设置/撤销管理员、解散 | 是 | 否 | 否 |

双人房间中的第二人默认为成员，房主可提升其为管理员。播放列表上限 200 条。Leader 固定为房主；本地文件添加者为该条目唯一供片者，管理员也可供片。角色决定控制权，供片身份不赋予控制权。

## 3. 创建与加入

1. 首次启动生成设备密钥，昵称仅用于展示。
2. 房主创建房间，登记信令服务并生成一次性邀请链接。
3. 受邀设备连接信令，验证邀请并证明自身身份；房间已满则拒绝新身份。
4. 建立 P2P，验证双方身份和连接指纹；失败不得接收业务数据。
5. 获取权限、列表与播放快照，校准时钟，缓冲后追赶当前进度。
6. 新成员的连接/缓冲不暂停现有播放。

邀请一次成功接纳一个身份；同身份网络重试幂等。重新邀请其他人时生成新凭证。成员离开后释放在线席位，重连仍受当前人数与身份授权校验。

## 4. 添加 URL

房主/管理员粘贴 URL → 检查 scheme 和媒体类型 → 探测时长与可播放性 → 提交条目 → 房主排序广播 → 每台设备独立探测并获取媒体。

仅接受无需应用专用登录、Cookie 或自定义请求头的点播资源；带查询签名的链接可用，但应提示过期风险并避免日志记录。拒绝网页地址、直播清单、DRM 和无法建立有限时间线的资源。

添加者可访问不代表所有人可访问。某端失败时只显示该端错误，不自动代理，也不打断另一端。HLS 的码率档位可以不同，但必须对应同一内容时间线。检测到资源变化或时长明显不一致时暂停该端并提示更换来源。

## 5. 添加本地文件

选择文件 → 检查媒体容器与平台可播放能力 → 对原始字节分片并生成签名清单 → 提交条目 → 接收方按需下载、校验、缓存，经 Range 桥交成熟播放器解码。当前实现不依赖桌面 FFmpeg 转封装，扩展名不能作为唯一可播放判据。

原生端与 Web 使用的解码能力可能不同；添加端可播不等于接收端可播。不能解码、浏览器不支持或资源损坏时，应向受影响端展示具体且可恢复的错误，不能静默冻结或宣称所有编码均已跨平台验收。

不兼容则拒绝并说明原因，不隐式转码。第一版先完成整个文件的切片和清单，再将条目标记为可播放；准备期间可继续看现有视频。这样首播准备时间随文件大小增长，但可避免未生成范围的 seek 和渐进清单复杂度。

视频字节仅存在供片端和观众缓存中，不进入信令服务器。文件路径、原始目录不对其他设备广播，展示名称单独提供。

## 6. 列表与播放

- 新条目添加后不自动打断当前视频；空房间首条进入就绪状态，等待授权用户点击播放。
- 排序仅影响后续播放；非当前条目删除不影响播放。
- 删除当前项时选择删除前的下一项；无下一项则停止并清空当前项。新选中项保持暂停，等待播放。
- 替换当前项视为新媒体，取消旧下载、重建缓冲，位置归零并暂停。
- 手动切换条目位置归零；保持原播放意图，未就绪成员自行缓冲。
- 自然结束由房主提交一次自动下一条；下一条从零播放，末项结束后停在结尾。新条目不可用则显示等待/错误，不静默跳过。
- 控制与列表共用一个顺序。过期的列表修改拒绝并刷新；播放/暂停/seek 请求以最新已确认状态为基础执行。
- 倍速初版提供 0.5、1、1.25、1.5、2 倍；同步纠偏可在选定倍速附近短暂微调。

## 7. 缓冲与同步

房间时间线持续前进，各端目标一致。当前视频初始缓冲建议为 10 秒可播放时长，短视频可缓冲剩余全部；缓冲目标可扩至 30 秒，按房间倍速换算。

某成员卡顿时其他成员继续；恢复者追赶当前时间线。seek 后优先下载目标附近分片，取消无关请求。暂停时暂停时间线，不把缓冲事件当作管理员操作。

## 8. 异常与生命周期

| 场景 | 行为 |
|---|---|
| P2P 断开 | 按 1/2/4 秒最多三次重试；失败显示不可达，提供手动重试 |
| 信令断开 | 现有 P2P 和播放继续；新加入或需重新协商的连接可能失败 |
| 信令重启 | 房主重新登记，旧邀请代次失效并生成新邀请；原成员通过身份恢复 |
| 房主离线 | 沿最后锚点继续当前条目，禁止新的共享控制和自动下一条；房主恢复后重新对齐 |
| 唯一供片者离线 | 播放现有缓存，缺片处等待；不宣称其他设备可恢复未收到数据 |
| 客户端休眠/恢复 | 恢复连接，刷新快照和时钟，再追赶；不保证后台持续播放 |
| 原文件被移除/修改 | 已切片的缓存仍可供片；缓存也不可用时条目标记错误，要求重新添加 |
| 应用退出/崩溃 | 第一版不承诺持久恢复房间；房主进程重启创建新会话 |

## 9. 页面与用户反馈

入口页：创建房间、粘贴邀请；房间页：视频主区、播放列表、成员；设置页：语言、主题模式、浅色主题色、深色主题色、缓存占用与清理、诊断入口。

全局要求见 [多语言与主题设置](APP-SETTINGS.md)，仅影响本设备，任何角色可修改，不影响房间同步。

成员只读房间进度，但保留本机音量和全屏。明确区分：连接中、准备文件、缓冲、追赶、房间暂停、源离线、房主离线、格式不支持和不可达。支持键盘操作、可访问标签及足够的焦点提示。

缓存清理不得破坏正在播放/供片的文件：使用中的缓存延迟清理或明确要求先停止。普通日志不记录邀请、完整 URL、密钥、完整 SDP 和文件路径。
