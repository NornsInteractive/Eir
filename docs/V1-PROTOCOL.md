# 第一版协议与安全规格

状态：协议草案；与产品范围一致，只有一个固定房主协调者，不实现分布式选主。本文给出实现约束；线格式和密码库互操作测试通过前不能宣称协议已冻结。

## 1. 身份、信任根与邀请

设备持有持久 Ed25519 密钥，deviceId 为公钥 SHA-256 摘要。私钥存平台安全存储，不进入普通配置和日志。房间创世记录绑定随机 roomId、ownerPublicKey、protocolVersion 和 sessionId，由房主签名。

邀请链接带信令地址、创世摘要、邀请 ID 和高熵随机令牌；令牌放 URL fragment，由客户端解析后仅经 WSS 提交，避免进入普通 HTTP 路径日志。房主签名邀请绑定房间、代次、到期时间和令牌摘要。用户持有邀请意味着可申请接纳，不等于管理员授权。

信令校验并原子消费邀请，绑定加入者公钥；房主签发 MEMBER_ADMIT 后才具备成员资格。相同身份重试返回相同接纳结果。恶意信令不能签发成员资格、替换创世根或提升角色，但可以拒绝服务、观察元数据。

信令重启后旧消费状态不可恢复，房主提升邀请代次；房主与成员拒绝旧代次的新接纳。原已接纳身份重连不重新消费邀请。不同设备之间不通过同昵称继承身份。

## 2. 编码与签名

控制信封使用 UTF-8 JSON。签名覆盖不含 signature 的信封，采用 RFC 8785 规范化，并加固定用途前缀；所有签名方/验签方必须通过相同测试向量。大整数禁止超过 JSON 安全整数范围，时间/位置采用整数毫秒，速率有限正数。

| 字段 | 含义 |
|---|---|
| protocolVersion | 第一版固定 1，不兼容版本拒绝 |
| roomId / sessionId | 房间与本次会话，阻止跨房和重启重放 |
| senderId / messageId / type | 来源、去重 ID 和消息类型 |
| aclVersion | 操作者依据的权限版本 |
| payload | 类型限定的载荷 |
| signature | 签名，含必要编码规范 |

接收处理：大小/结构 → 会话与身份 → 签名 → 当前权限 → 去重/序号 → 参数与状态约束。未知类型拒绝，不作为任意转发载荷。首版控制信封上限 64 KiB；快照和媒体清单超过上限时分块传输，完整摘要校验后应用。

同版本不同内容视为冲突，不按时间戳覆盖。状态更新需前序摘要链接，最新快照由在线房主确认；最大序号自报值不作为可信依据。

## 3. 连接握手

1. 经信令交换 SDP/ICE，限制消息体积、候选数量和发送速率。
2. DataChannel 打开后交换随机挑战和设备公钥。
3. 双方签名 roomId、sessionId、双方 deviceId、双方随机挑战与双方实际 DTLS 指纹。
4. 验证创世根、接纳记录及签名与实际连接指纹一致，再放行业务数据。

握手十秒未完成或验证失败即关闭连接。随机数一次性使用。插件不能提供所需实际指纹时属于阻塞问题，必须调整适配或方案，不能省略绑定检查。

## 4. 消息组

| 消息 | 载荷与规则 |
|---|---|
| MEMBER_ADMIT / ACL_UPDATE | 房主签名的成员接纳/管理员增撤，含版本及前一摘要 |
| CONTROL_REQUEST | requestId、动作、参数、baseSeq，保留操作者签名 |
| ROOM_COMMIT | 房主签名 seq、前一摘要、原请求/系统原因、新状态及生效时间 |
| COMMIT_ACK / RESYNC_REQUEST | 已应用序号、缺失范围；房主补发或给快照 |
| ROOM_SNAPSHOT | 权限、列表、播放锚点、最后序号与链摘要，房主确认 |
| TIME_PING / TIME_PONG | probeId、四时间戳所需数据，来源需认证 |
| PEER_STATUS | 实际位置、缓冲、错误和状态所对应的 itemId/seq，仅参考 |
| MANIFEST_OFFER / MANIFEST_GET | 清单摘要、分块范围、来源签名 |
| SEGMENT_REQUEST / CHUNK / CANCEL | 请求 ID、媒体 ID、分片索引、偏移和长度 |
| LEAVE / ROOM_CLOSE | 成员离开或房主签名解散；离线端恢复后才得知 |

允许的动作是播放、暂停、seek、设置倍速、添加/删除/排序/替换/切换条目。房主发起的自动下一条等系统操作也需签名并限定触发条件。管理员请求不允许隐含修改 ACL。

实现中的片尾停止提交 `ended_stop` 由房主在当前最后一项实际完成时发出，`params.positionMs` 为非负整数，优先使用已知媒体时长。应用后状态为暂停、位置为该片尾时间，供晚加入快照使用；不能沿用最初播放时的锚点位置。旧提交没有该字段时保留原有位置作为兼容回退；新版本发送方始终提供该字段。再次播放通过独立播放提交将位置归零。

## 5. 排序与撤销

房主统一递增 seq，同一 requestId 只提交一次。客户端仅按连续 seq 应用；缺号进入补齐，不能用后来提交静默覆盖缺失授权更新。快照只接受房主签名且序号不倒退。

ACL 更新同样进入房间提交顺序。权限以该请求提交时已确认 ACL 为准；撤销之后到达的旧管理员请求拒绝。隔离端尚未收到撤销时无法瞬间得知，恢复后按房主链校正。

发送者身份真实不等于行为可信：合法管理员仍可恶意暂停。若房主设备本身恶意或私钥泄露，本版不保证房间一致与安全。

## 6. 媒体清单与分片

清单字段：mediaId、源 deviceId、codec/profile、时长、init 大小/哈希、每片 index/startMs/durationMs/size/hash，清单由源设备签名。mediaId 使用规范化核心清单摘要；签名及 mediaId 自身不参与该摘要，避免循环定义。

添加请求绑定清单摘要与源身份，经授权提交后才成为可请求媒体。不使用文件名作内容 ID，不广播原路径。init 同样必须校验。

CHUNK 二进制帧带 protocolVersion、requestId、mediaId、segmentIndex、offset、payloadLength。具体字段宽度与字节序在协议冻结时固定；接收端限制总长度、并发组装量、超时和重叠范围，拒绝越界、冲突重叠与不匹配请求。旧请求数据不能写到新条目缓存。

片段完整 SHA-256 校验通过后才原子发布。坏片丢弃，有限重试后报错，第一版只有一个源不能伪装成已换源。明文哈希不代替签名清单，DTLS 不代替应用授权。

## 7. 其他安全边界

- 邀请、私钥、查询令牌、完整 SDP 和本地路径均脱敏，不进入普通遥测。
- URL 只允许 HTTPS，禁止 file/data/javascript 等输入；外部命令使用参数数组，不经过 shell 拼接。
- 本机 HTTP 随机令牌、仅 loopback、缓存路径白名单、无目录遍历，令牌与路径不作为远端协议字段。
- 各类请求都有速率与资源上限；信令不能承接媒体分片，拒绝超大 SDP/ICE。
- P2P 对端可能看到 IP；合法观众可以保存已收到数据，应用不能承诺阻止复制。
- 本版无 TURN，无公网视频存储，无踢人/封禁功能；解散不能远程擦除观众缓存。
